# 通信检查与手动校准

适用：本仓库锁定的 LeRobot 0.6.1；幻尔 SO-ARM101 标准版。核实日期：2026-10-12。

## 接线与身份

两只臂底座夹紧，舵机串接线保持原样，USB 和配套电源均接好。关闭 ServoStudio、遥操作程序等可能占用串口的应用。整个校准过程由人手动移动关节，托住连杆，避免失去支撑后下落；遇到明显阻力、线材绷紧或结构碰撞就停止，不强行掰动。

| 角色 | 本次端口 | 连接板 USB 序列号 | 固定设备 ID |
| --- | --- | --- | --- |
| 黑色主臂 leader | COM4 | 5C82109341 | hiwonder_leader |
| 白色从臂 follower | COM3 | 5C82109737 | hiwonder_follower |

脚本按 USB 序列号找到当前 COM 口，所以端口编号变化仍可识别角色。更换控制板后必须核对并修改 `hardware.py` 中映射。成品无需执行 `lerobot-setup-motors`，也无需拔开关节串接线。

```powershell

```

也可只检查一只：在命令末尾添加 `--arm leader` 或 `--arm follower`。

成功时显示两只臂各 ID 1–6、型号码 777、原始位置、力矩状态和工作模式，最后显示 `PASS`。报告保存在 `outputs/communication-check.json`。这个脚本只发送 ping/read，不写参数、不改变力矩、不调用普通机器人连接流程。原始位置不是角度；型号码相同也不证明两臂的减速比、扭矩相同。

2026-10-12 实机运行通过，12 个舵机均正常响应，力矩读数均为 0，模式均为 0。串口错误或舵机未响应会返回非零退出码，并保存失败结果。

## 2. 先校准黑色主臂

```powershell
.\experiments\lerobot\run.ps1 python calibrate_arm.py --arm leader
```

脚本首先只读检查设备。若力矩仍开启会退出，需要先结束其他控制程序、支撑机械臂并排查；不自动解除正在承重的姿态。它会打印校准文件位置，提示你托住机械臂并准备好。准备完成再按 Enter。

校准会写入工作模式、解锁/关闭力矩、零位偏移和关节范围。脚本直接连接总线，调用官方 `calibrate()`；不走普通从臂 `connect()/configure()`，不写运动目标、不启用力矩。操作前自动备份已有 JSON 及电机里的偏移/范围，备份在该臂的 `backups/时间戳/` 中。备份不是完整固件配置，也不会自动恢复。

### 提示 A：已有校准文件（首次通常不会出现）

`Press ENTER to use provided calibration file ... or type 'c' ...`

重新校准时输入 **c，再按 Enter**。直接 Enter 会把旧文件中的参数写回舵机并结束，不会重新采集范围。

### 提示 B：摆到中间姿态

`Move ... to the middle of its range of motion and press ENTER...`

手动把各关节放在活动范围中间附近，按照厂商的主臂/从臂参考姿态对照；两臂应采用对应的机械姿态。不要以开箱折叠姿态直接确认。夹爪放在开合范围中间，腕部旋转也应处于参考方向。姿态摆好并托稳后按 Enter，这一步会写零位偏移。

- [厂商主臂参考图](https://docs.hiwonder.com/projects/LeRobot/en/latest/_static/media/chapter_1/section_4/image_2.png)
- [厂商从臂参考图](https://docs.hiwonder.com/projects/LeRobot/en/latest/_static/media/chapter_1/section_4/image_14.png)
- 本地资料中的 `4.1.1 从臂校准.mp4` / `4.1.2 主臂校准.mp4` 可配合查看；界面细节以当前脚本提示为准。

### 提示 C：记录活动范围

`Move all joints except 'wrist_roll' ... Recording positions. Press ENTER to stop...`

此时终端持续显示各关节最小值、当前位置和最大值。**先不要按 Enter。** 依次缓慢移动下列五个关节，让软件记录它们正常可达的两端；可往返一次，观察数值是否更新。保持线材松弛，不用力撞机械止挡。

| ID | 名称 | 手动动作 |
| --- | --- | --- |
| 1 | shoulder_pan | 底座上方的肩部左右转动 |
| 2 | shoulder_lift | 大臂上下抬落，手托连杆 |
| 3 | elbow_flex | 肘部弯曲、展开 |
| 4 | wrist_flex | 腕部俯仰 |
| 6 | gripper | 夹爪打开、闭合，手指避开夹持处 |

**ID 5 `wrist_roll` 不参加这一步的范围扫描。** 当前官方实现将其编码器范围设为 0–4095；这不代表装配后的线材允许无限旋转。它在上一步仍需正确摆放参考方向。

五个关节都移动过、每行的最小值小于最大值后，托稳机械臂，再按一次 Enter 完成。不要只动一个关节就结束，也不要把小幅摆动误当作完整范围。

### 成功标志

先出现 `Calibration saved to ...`，接着脚本显示：

```text
PASS: calibration saved and motor registers match.
```

这表示校准文件保存成功，寄存器回读匹配；软件不能自动判断你是否覆盖了合适的机械范围，因此仍需人工检查和后续小范围遥操作验证。

- 主臂：`outputs/calibration/leader/hiwonder_leader.json`
- 从臂：`outputs/calibration/follower/hiwonder_follower.json`

以上路径相对 `experiments/lerobot/`，目录已被 Git 忽略，但应自行备份。后续遥操作/采集必须沿用相同设备 ID，并显式传入这两个 `calibration_dir`；否则默认缓存路径找不到本次文件，可能再次要求校准。主从两边统一 `use_degrees=True`。

异常时 Ctrl+C 可终止并关闭串口。若已经进入零位或范围阶段，部分校准寄存器可能已经改变，重新运行完整校准后再使用，不直接启动遥操作。

## 遥操作问题诊断（2026-10-12）

用户报告首次 10 Hz、相对目标限制 1 的遥操作存在卡顿和疑似单向运动。原因尚未确定，不能直接以通信通过认定跟随正确。主臂后来重新校准，当前肘部范围为 360–4156；上述较早的范围数值属于先前校准记录。

先退出其他控制程序，在仓库根目录运行：

```powershell
.\experiments\lerobot\run.ps1 python teleop_test.py
```

`teleop_test.py` 是诊断用途的带动力程序。按 USB 序列号识别两臂，检查校准回读、力矩关闭及反馈模式；用户摆好相近的中间姿态并按 Enter 后，检查角度差（关节不超过 15°，夹爪不超过 20 个归一化单位），才启动。配置采用官方 0.6.1 驱动；使能前把从臂当前位置写为目标，避免沿用旧目标。请求频率 60 Hz，实际频率由日志判断。现已取消“目标与测得从臂位置最多相差 5°”的限制，改为限制下发目标轨迹的变化速度：旋转关节默认 60°/秒，夹爪默认 50 个归一化单位/秒。轨迹基于上次发送的目标推进，不因从臂暂时停住而固定在 5°位置偏差；这只是目标轨迹限速，不能保证实际机械速度或碰撞保护。保留活动范围边界和 24 原始刻度的端点余量，不允许把目标发到 0–4095 之外。

默认运行 60 秒，可用 `--seconds 30` 缩短；结束或 Ctrl+C 后逐关节尝试关闭从臂力矩，提前托住机械臂。若通信失败导致力矩无法关闭，终端会提示断开舵机电源。异常位置跳变、跟随误差过大、明显位置越界或读取耗时超过 200ms 会终止测试。读数允许超出校准记录端点至多 32 原始刻度（旋转关节约 2.8°），作为本地诊断容差；不扩大下发目标范围，0–4095 编码检查仍严格。小幅超出会记录 `calibration_excursions`，持续或显著超出仍需复核校准。初次只在中间范围缓慢移动一个主臂关节，往返几次，其余保持不动。不要在故障未查清时绕过检查或扩大限幅。

每次日志保存至 `outputs/teleop-tests/时间戳/`：`metadata.json` 包含校准、端口和终止原因，`samples.jsonl` 包含主从原始位置、归一化位置、实际发送目标、限幅标记、读写耗时及周期间隔。当前 schema 4 中 `clip_reasons.speed` 表示目标轨迹限速，`clip_reasons.range` 表示活动范围限幅，两者可以同时出现；旧 schema 的 `clip_reasons.step` 是之前相对测得位置的步幅限制。读取校验失败的原始快照也会写入日志。启动时的目标必须在目标内边界内，之后的测得位置由独立观测检查处理。主从读取是先后进行的，并非硬件同步采样。终端每秒输出摘要，无需复制大量数据。`--dry-run` 仅验证身份与文件，不打开串口。

实机记录 `20261012-210832-315639`：667 帧、11.30 秒，实际频率 58.93 Hz；读写耗时中位数 2.85ms、95 分位 3.33ms、最大 4.06ms。肩部旋转与夹爪均观察到正反向运动；肘部和腕部旋转变化不足，尚未验收。腕部接近上端时，主臂要求 102.73°，从臂目标上限 96.92°，因此有活动范围限幅。测试在主臂腕部读到 3198 时停止，仅比校准上限 3197 多 1 刻度（约 0.088°）；原来的零容差检查过严。已修正上述观测容差、限幅分类和错误帧日志，8 项离线回归检查及 dry-run 通过；修正版尚待真机复测。

## 遥操作限幅问题与复测结论

日期：2026-10-12。**本次回向不响应的主要问题来自本地测试代码盲目添加的相对位置限幅；移除后用户确认恢复，肩部正反向实机响应也得到日志验证。**

初期测试为避免远距离目标，先后设置了 1°、5°相对从臂测得位置的目标限幅，未充分验证它对带负载位置控制的影响。它不是硬件活动范围，也不是单纯降低动作速度。只要从臂停住，下发目标就固定在测得位置附近，主臂继续移动也无法增加舵机看到的位置偏差。例如从臂 77°、主臂 59°时，旧目标一直约为 72°；这可能使该姿态下的驱动力不足，形成持续无法回转的现象。错误在本实验对上游选项的选择与使用，不能据此认定上游 LeRobot 本身存在缺陷或电机最大扭矩不足。

修复采用独立的目标轨迹限速，基于上次发送目标向主臂请求推进，取消固定的测得位置差限制。当前关节 60°/秒、夹爪 50 单位/秒是实验默认参数，并非已证明普遍适用的安全值；硬件报警、活动范围和异常退出检查仍各自保留。

最新复测 `20261012-214851-864924` 使用修正版 schema 4，运行全臂遥操作 59.99 秒、3536 帧，实际频率 58.93 Hz，正常结束。`shoulder_lift` 实测范围约 -30.24°至 61.10°，可观测正向变化 466 帧、反向变化 395 帧（计数阈值为每帧 0.15°），主从差绝对值中位数 1.76°；采样到的舵机回包错误位均为 0。前一轮 `20261012-214753-670036` 也观察到肩部双向移动，由用户主动结束。该证据支持本次肩部回转问题已恢复；肘部等关节的完整往返及全负载能力尚未据此验收。

后续原则：不因为“更保守”就加入任意限幅；先说明限制对象、单位与依据，检查它是否改变控制器出力或让目标停滞。需要平滑时限制目标轨迹变化率，并分别验证正常正反向与异常情形。开发约定已写入本目录的 [AGENTS.md](AGENTS.md)。
