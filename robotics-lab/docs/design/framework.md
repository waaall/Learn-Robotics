# 软件框架与运行职责

日期：2026-10-17。本文记录实现组织，长期产品目标保留在整体需求文档中。

## 1. 运行职责

| 模块 | 输入 | 输出与职责 |
| --- | --- | --- |
| 实验目录 | 明确版本的实验定义 | 展示教学内容、模型引用、初态和观测指标 |
| 独立数值计算 | 实验标识与可选时长 | 从预设初态运行，输出采样曲线、物理指标及来源记录 |
| 查看器适配 | 实验模型、初态和端口 | 启动官方 Studio WebViewer；该会话独立持有交互仿真状态 |
| 会话管理 | 启动、状态和结束请求 | 管理一个查看器子进程，检查 HTTP 就绪与进程错误 |
| 网页界面 | 目录、系统能力、会话和运行结果 | 实验选择、说明、交互窗口、独立验证及记录下载 |

## 2. 技术选择

- Python 3.12、MuJoCo 3.16.0：物理实验和官方查看器接入。
- FastAPI：本地应用接口及构建后页面分发；数值运行使用同步接口，不阻塞异步事件循环。
- React、TypeScript、Vite：目录、内容和数据界面；前端仅承担显示与用户操作。
- 官方 WebViewer：浏览器显示与原生 Python 仿真配合，采用上游默认查看器与步进、历史插件。
- Linux/WSL：官方 WebViewer 的运行路线；Windows 的数值功能与网页资源构建单独验证。

没有引入第二个物理引擎或另写三维渲染器。现有 `experiments/mujoco_physics` 保持独立；本项目收录两份带来源注释的简化场景，逐步建立自己的实验接口。

## 3. 状态与数据

交互仿真在查看器子进程中运行，状态由官方仿真侧管理。外层网页当前只管理启动与结束，暂停、单步和状态编辑使用官方控件。

独立数值验证使用另一份模型与状态，始终从实验预设初态运行。保存模型哈希、初始状态、时长、步长、运行库版本、采样曲线和物理指标。界面明确标记这些曲线不反映交互窗口中的修改。

每个积分步后重新求值派生量，将观测刷新到当前时刻；该计算方式用于一致性检查，不作为仿真吞吐性能基准。显示曲线降采样，物理计算仍执行全部积分步。

## 4. 生命周期与部署

- 查看器通过独立子进程启动。首次 HTTP 响应成功后记录就绪，后续通过进程退出状态报告终止；就绪状态不代表每个浏览器都已完成渲染。
- 45 秒超时只用于尚未就绪的启动过程，已经就绪的会话不再受启动期限限制。
- 同时只允许一个查看器会话；切换实验前结束当前会话。
- 应用正常关闭时终止其查看器子进程；强制杀死应用的异常清理仍需后续完善。
- 查看器使用动态端口。WSL 本机访问与远程 Linux 访问分别验证；当前不具备统一端口的查看器代理。
- Windows 与 Linux 使用不同虚拟环境目录，依赖版本来自同一项目锁文件。

## 5. 后续接口研究

1. 通过官方仿真侧插件接入控制器，并区分物理步长、控制频率和显示频率。
2. 将交互会话状态与指标接入外层页面，定义状态同步、重置和控制器状态恢复语义。
3. 增加模型目录与场景适配，固定模型来源、版本和许可证记录。
4. 对经验证的端口代理或查看器嵌入方式进行封装。

以上属于后续实现，当前接口不宣称已支持任意策略、模型或实验组合。
