# 首版框架验证记录

日期：2026-10-17。本文记录本机实测结果，不代表长期产品需求已全部实现。

本文对应首次框架提交。新增课程、Panda 和实时控制的验证见 [课程验证记录](courses.md)。

## 1. 验证环境

| 项目 | 实测值 |
| --- | --- |
| Windows Python | CPython 3.12.10 |
| WSL Ubuntu Python | CPython 3.12.3 |
| MuJoCo | Python 与原生库均为 3.16.0 |
| Node.js / npm | 24.21.0 / 11.19.0 |
| 前端 | React 19.2、TypeScript 5.9、Vite 7.3.7；精确版本见锁文件 |
| 部署 | WSL 内本地服务，Windows 浏览器通过 localhost 访问 |

Python 依赖由 `uv.lock` 固定，前端依赖由 `frontend/package-lock.json` 固定。两个操作系统使用独立虚拟环境。

## 2. 官方查看器安装包

- Windows：数值仿真可以运行；导入官方网页查看器失败，缺少 `headless_ui`、`state_payload` 以及浏览器 JS/WASM 资源。
- Linux：官方 wheel 中上述组件齐全，`python -m robotics_lab doctor` 返回 `available: true`，随后实际启动并完成浏览器渲染。
- 依据：[MuJoCo 3.16.0 的 WebViewer 构建配置](https://github.com/google-deepmind/mujoco/blob/3.16.0/python/mujoco/experimental/studio/web/CMakeLists.txt) 显式在 Windows 跳过网页查看器扩展，并说明其浏览器客户端未随 Windows wheel 分发。没有将 Windows 缺件归结为本项目配置错误。

当前适配使用上游 `experimental.studio` 接口，固定到 3.16.0。升级版本需要重新验证启动、插件、资源与浏览器协议。[官方启动实现](https://github.com/google-deepmind/mujoco/blob/3.16.0/python/mujoco/experimental/studio/launch_web.py)

## 3. 自动检查

Windows 与 WSL 分别执行以下命令，均为 10 项测试通过：

```shell
python -m unittest discover -s tests -v
```

覆盖内容：实验初态恢复、无阻尼单摆的能量与运动、落球稳定支撑及软接触穿透、非法时长、运行记录保存与读取、实验标识和记录标识校验、缺少查看器时的错误报告、启动超时及运行阶段的会话存活规则。

前端执行 `npm run build --prefix frontend`，TypeScript 检查与 Vite 生产构建通过。

当前 Starlette 的 TestClient 对 `httpx` 发出弃用提示；本次测试全部通过。后续更新测试依赖时应复核其支持的客户端。

## 4. 物理计算结果

默认时长均为 2 s，物理步长为 0.001 s，执行 2000 步。

| 实验 | 结果 |
| --- | --- |
| 无阻尼单摆 | 初始角度 0.4 rad，最大机械能变化约 5.68 × 10⁻¹⁴ J |
| 1 kg 落球 | 末段平均法向支撑约 9.81 N，末态球心高度接近 0.1 m |
| 落球冲击 | 最大穿透约 0.02861 m，属于当前软接触参数下的冲击峰值，不能作为稳定穿透量使用 |

结果文件记录模型 SHA-256、预设初态、时长、步长、库版本、采样与指标。当前曲线来自独立计算，不读取官方窗口中的交互修改。

## 5. 浏览器实测

- 浏览器从 Windows 访问 WSL 的页面和动态查看器端口成功。
- 切换单摆与落球，目录说明、观测量与计算指标随实验改变。
- 两个场景均由官方查看器实际渲染，能够观察摆杆或球体与地面。
- 官方独立窗口的暂停、向前推进和多窗口控制权切换已操作。推进采用官方插件语义，尚未将一次按钮操作定义为本平台固定数量的物理积分步。
- 1440 px 桌面布局与窄侧栏布局均查看；窄窗口的官方左右面板会压缩三维区域，提供独立窗口入口。
- 已通过网页运行独立验证并生成结果曲线与记录下载入口，记录读取由 API 测试校验。
- 修复后重新启动单摆会话，超过 45 秒启动期限后仍正常运行；通过页面结束会话后，状态接口返回空值，WSL 进程检查确认查看器子进程已退出，应用进程继续运行。

验证期间发现会话管理的启动期限误用于运行阶段，可能因一次 HTTP 探测延迟而终止已经就绪的进程。已修复为仅检查首次启动，并补充两项生命周期回归测试。
